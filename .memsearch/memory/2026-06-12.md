#### 4.2 局限性分析

1. **Node.js 依赖** (`js_workflow.py:75`)
   - 需要系统安装 Node.js，无 Node.js 时 JS 工作流不可用
   - 桥接脚本使用 ES Module (`import`)，需要 Node.js >= 12

2. **进程间通信开销** (`js_workflow.py:85-151`)
   - 每次 JS 调用 `agent()` 都需要序列化→stdout→Python 反序列化→执行→序列化→stdin→Node.js 反序列化
   - 高频调用时延迟显著

3. **错误传播不完善** (`js_workflow.py:323-332`)
   - Python 端异常用 `traceback.format_exc()` 序列化传回
   - Node.js 端只做了基本的 error 检查 (第 365-373 行)

4. **超时机制粗糙** (`js_workflow.py:154-178`)
   - 整体超时 600s (可配置)，超时直接 `process.kill()`
   - 没有单个 agent 调用的超时传播到 JS 端

5. **无断点续传** 
   - JS 脚本执行失败后无法从中间恢复
   - 临时目录在 `with` 块结束时销毁

6. **budget 功能空壳** (`js_workflow.py:481-487`)
   - `globalThis.budget` 只有简单的 `_used` 计数
   - 没有与 Python 端的 `BudgetTracker` 实际联动

   - 当前实现是每个 item 独立流过所有 stage
   - 不支持跨 item 的阶段聚合/等待

   - 无 `isolation` (worktree) 实际实现

### Claude Code Dynamic Workflows 调研 + 实现补全

**用户命令：** "看看Claude 的js的workflow编排的js文件"

#### 调研内容

**Claude Code CLI 官方 `/workflow` + JS 编排核心设计：**
用 JS 文件通过 `agent() / parallel() / pipeline() / phase() / log() / budget` 等全局原语确定性编排多个子 Agent。

**JS API：**
- `agent(prompt, opts)` — 调子 Agent，支持 label/schema/model/isolation/agentType
- `parallel([thunks])` — 并发执行，有屏障（等全部完成）
- `pipeline(items, ...stages)` — 无屏障流水线
- `phase(title)` — 标记阶段
- `log(msg)` — 输出日志
- `budget` — `{ total, remaining(), spent() }` Token 预算追踪
- `workflow(name/scriptPath, args)` — 嵌套执行子 Workflow

**脚本结构：**
```js
export const meta = { name, description, phases: [{title, detail}] }
export default async function () { ... }
```

**6 大编排模式：** Classify-and-Act / Fan-Out-and-Synthesize / Adversarial Verification / Generate-and-Filter / Tournament / Loop-Until-Done

**核心机制：** IPC 协议（`__IPC__:` stdin/stdout）、Token Budget 硬限制、Deterministic Resume、Worktree Isolation、最大 16 并发 / 1000 Agent

**生态（2026年6月）：** 内置在 Claude Code CLI（需 Pro/Team 订阅）；开源复刻 Open Dynamic Workflow（MIT）；workflow-cookbook 织经 29 章配方手册；omegacode npm 包；npx workflow-pack 10 个预装

#### 项目实现 vs 官方对比

**对齐的：** Node.js 运行时 + bridge IPC、agent/parallel/pipeline/phase/log/budget、Schema 验证、命令系统 `.claude/commands/`（command.py 18字段）、Subagent Profile `.claude/agents/`（registry.py 6内置类型）、工具白/黑名单权限约束

**此前缺失的（已补全）：**
- ✅ **Resume 缓存** — `_resume_cache` 字典 + `_make_cache_key()` 排除动态字段，命中直接返回，提供 `cache_stats()` 
- ✅ **workflow() 嵌套** — `_resolve_workflow_by_name()` 查找 `.claude/workflows/` / `workflows/` / `~/.claude/workflows/`
- ✅ **多模型路由** — 每个 agent() 可指定 model，`budget.modelSpent` 按模型统计，`budget.report()` 汇报给 Python BudgetTracker

**修改文件：**
- `core/multi_agent_v2/workflow/js_workflow.py` — 3功能实现 + 桥接脚本增强
- `core/multi_agent_v2/workflow/models.py` — `WorkflowResult` 新增 `metadata` 字段
- `example_workflow.js` — 展示新功能用法
