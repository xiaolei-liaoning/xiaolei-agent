# Workflow 模板引用重构设计

## 问题

LLM 生成 JS workflow 时，`workflows/.workflow_prompt_template.md` 中 10 个模板（共 400+ 行代码）和任务描述、规则、反模式全部塞在同一个 prompt 里。LLM 看到的模板被上下文中的其他噪声稀释/污染，导致生成的 workflow 质量不稳定。

## 方案

只改 `_llm_write_workflow` 的拼接逻辑，不动桥接引擎、不添加运行时、不后置校验。

### 改动前

```
prompt = 匹配表(21行) + 固定结构(18行) + API规则(28行)
       + 10个模板代码(400行) + 反模式(6行) + 任务
```

### 改动后

```
Step 1 — 匹配编号
  prompt = 匹配表(21行) + 任务
  → LLM 返回编号，如 "⑤" 或 "⑤+②"

Step 2 — 靶向拼接
  从 .workflow_prompt_template.md 提取对应编号的示例代码段
  拼接:
    [规则摘要(3-5行)]
    [模板⑤ 代码段]
    [模板② 代码段]  (如果有多编号)
    [任务]
  → LLM 写 workflow

Step 3 — 执行
  不变，直接跑生成好的 workflow
```

### 关键细节

- 匹配阶段的 prompt 只包含快速匹配表 + 任务（约 30 行），不含任何示例代码
- 支持多编号返回（用 `+` 分隔），LLM 根据任务复杂度自行判断
- 拼接时从 `.workflow_prompt_template.md` 中用正则截取 `### 编号` 到下一个 `---` 之间的段落
- 不引入新文件、新依赖、新运行时
- 保留 fallback：如果匹配失败或模板提取失败，回退到当前整段 prompt

### 不做的

- 不写模板为独立 JS 文件（模板仍然是 prompt 里的示例文本）
- 不加 post-exec 校验
- 不加运行时执行引擎
- 不改变 bridge.mjs / js_workflow.py

## 测试

- 匹配 10 种任务的编号输出是否正确
- 匹配后提取的代码段是否正确对应编号
- 多编号（如 "⑤+②"）是否正确拼接
- 生成的 workflow 语法正确、可执行
- 回退路径是否正常工作
