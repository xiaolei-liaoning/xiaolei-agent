# 深度分析执行流程与结果：子代理到底是不是 task？

## Goal

确定执行日志中出现的 `[子代理]` 究竟由哪个工具产生——是 `task`、`orchestrate`，还是两者共用同一引擎——并给出可复现的、基于代码行的结论，让后续任何会话都能一眼判断"这次调的是 task 还是 orchestrate"。

## Current context / assumptions

- 项目路径：`/Users/leiyuxuan/Desktop/小雷版agent_副本`（git 分支 `v1-architecture-fix`）。
- 日志样本（session 5e22f219 / 10a878cf）里**同时**出现了 `◆ task` 和 `◆ orchestrate`，两者都伴随 `[子代理]` 前缀输出。用户疑惑：`[子代理]` = task？orchestrate 到底是什么？
- 已确认（只读追踪，结论先行）：
  - `task` 工具 handler = `_handle_task`（`tool_registry.py:1615`）→ 调 `spawn_subagent`（单个子代理）。
  - `orchestrate` 工具 handler = `_handle_orchestrate`（`tool_registry.py:1642`）→ 调 `orchestrate_subagents`（`spawn.py:390`），其内部**对每个 DAG 任务再调 `spawn_subagent`**（`spawn.py:453`）。
  - 因此 **`task` 和 `orchestrate` 共用同一个子代理执行引擎 `spawn_subagent`**，只是入口不同：task=单发，orchestrate=DAG 并行发。
  - `[子代理]` 前缀来自 `spawn.py:65` 的 `_tag = "子代理"`，在 `_drain_print_queue` 里对**任何**经 `spawn_subagent` 产生的输出统一加前缀。所以 `[子代理]` 这个标签**无法区分** task vs orchestrate。

## Architecture / proposed approach

不修改任何逻辑代码（本任务是"分析+结论固化"，不是功能改动）。产出两份东西：
1. 一段**可独立运行的诊断脚本** `scripts/trace_subagent.py`，用纯静态检查（正则 + AST 或简单 grep 汇总）扫出"哪些路径会调 `spawn_subagent`、各自入口工具名是什么"，输出一张映射表，供任何会话复用。
2. 一份**结论文档** `docs/subagent-vs-task.md`，把上面代码行证据 + 日志判读规则写清楚。

核心判读规则（写入文档）：
- 日志行 `◆ task · description=...` → 这次是**单子代理**（task 工具）。
- 日志行 `◆ orchestrate · tasks=[...]` → 这次是 **DAG 并行多子代理**（orchestrate 工具）。
- `[子代理]` 前缀本身**只说明"有一个子代理执行了"，不代表工具名**。要判断工具名，必须看调用它的那行 `◆ task` 还是 `◆ orchestrate`。

### Task 1 — 写诊断脚本，静态确认"谁调用 spawn_subagent"

新建 `scripts/trace_subagent.py`（目录 `scripts/` 已存在于项目根）：

```python
"""静态确认：task 与 orchestrate 是否共用 spawn_subagent 引擎。"""
import os, re, glob

ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))

def find_calls(filepath, fn_name):
    hits = []
    with open(filepath, encoding="utf-8") as f:
        for i, line in enumerate(f, 1):
            if fn_name in line and not line.strip().startswith("#"):
                hits.append((i, line.strip()[:100]))
    return hits

spawn_calls = []
for path in glob.glob(os.path.join(ROOT, "core", "**", "*.py"), recursive=True):
    if "__pycache__" in path:
        continue
    for line_no, text in find_calls(path, "spawn_subagent"):
        spawn_calls.append((path.replace(ROOT + "/", ""), line_no, text))

print("=== 所有调用 spawn_subagent 的位置 ===")
for p, n, t in spawn_calls:
    print(f"  {p}:{n}  {t}")

print("\n=== 入口工具映射 (tool_registry.py) ===")
reg = os.path.join(ROOT, "core/multi_agent_v2/tools/tool_registry.py")
for funcname in ("_handle_task", "_handle_orchestrate"):
    for line_no, text in find_calls(reg, "async def " + funcname):
        print(f"  {funcname}: L{line_no}")
    # 找它们调用的 spawn 函数
    for line_no, text in find_calls(reg, funcname):
        print(f"    -> 调用行: L{line_no} {text}")
```
