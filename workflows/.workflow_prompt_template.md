# Workflow 生成 Prompt 模板

当用户要求生成 JS Workflow 时，按以下规则写：

## 固定结构

```js
export const meta = {
  name: "简短名称",
  description: "一句话描述",
  phases: [
    { title: "阶段1", detail: "说明" },
    { title: "阶段2", detail: "说明" },
  ],
}

export default async function () {
  // ...
}
```

## API 使用规则

### agent(prompt, opts)
- 必须始终传 `label` — 用于进度显示和日志
- 复杂任务传 `model: "claude-sonnet-4-6"`，简单任务传 `model: "claude-haiku-4-5"`
- 最终结果输出的 agent 传 `isFinal: true`
- 需要 JSON 输出时传 `schema: { type: "object", properties: {...} }`
- 需要限制子 Agent 能力时传 `agentType: "Explore"` 或 `"Plan"` 或 `"Coder"`

### parallel([thunks])
- 参数必须是函数数组：`[() => agent(...), () => agent(...)]`
- 不能直接传 Promise 数组：`[agent(...), agent(...)]` ❌
- 内部 agent 调用要传 label 方便定位失败

### pipeline(items, ...stages)
- 每个 item 独立流过所有 stage — 适合批处理
- stage 签名: `(prevResult, originalItem, index) => newResult`
- 出错返回 null 不影响其他 items

### phase(title)
- 每个 phase 必须对应 meta.phases 中的一项
- 阶段名要有语义，不要用"步骤1"、"步骤2"

### budget
- 最终输出时调用 `budget.remaining()` 看余量
- 用 `budget.modelSpent` 看各模型用量

### workflow(nameOrRef, args)
- 调用子 workflow 时用
- 子 workflow 通过全局 `args` 获取参数

## 必选字段检查清单
- [ ] meta.name 非空
- [ ] meta.description 非空
- [ ] meta.phases 至少一项
- [ ] 每个 agent() 有 label
- [ ] parallel() 内是 thunk 不是 Promise
- [ ] 最终 agent 有 isFinal: true（如果需要 schema）
- [ ] 所有 agent 调用有 await
- [ ] export 关键字正确
- [ ] async function 正确

## 6 种编排模式速查

### 1. Fan-Out-and-Synthesize（并行收集→汇总）
适用：技术调研、数据收集、多源分析
```js
phase("收集")
const results = await parallel(items.map(item => () => agent(`研究${item}`)))
phase("汇总")
return await agent(`综合: ${results.join("\n")}`, { isFinal: true })
```

### 2. Adversarial Verification（产出→反驳验证）
适用：代码审查、事实核查、方案评估
```js
phase("产出")
const output = await agent("写方案")
phase("验证")
const verdict = await agent(`反驳以下方案：${output}`, { agentType: "Explore" })
```

### 3. Classify-and-Act（分类→分支处理）
适用：客服分流、问题分类、路由转发
```js
phase("分类")
const category = await agent("分类这个请求")
phase("处理")
if (category.includes("技术")) { await agent("技术处理") }
else { await agent("非技术处理") }
```

### 4. Generate-and-Filter（批量生成→筛选）
适用：创意生成、候选方案、文案创作
```js
phase("生成")
const candidates = await parallel([...Array(5)].map(() => () => agent("生成一个方案")))
phase("筛选")
const best = await agent(`从以下选最优：${candidates.join("\n")}`)
```

### 5. Tournament（多方案→两两对比）
适用：方案选优、排名、评估
```js
phase("生成")
const options = await parallel([...])
phase("对比")
// 两两对比…
```

### 6. Loop-Until-Done（循环直到满足条件）
适用：迭代优化、Bug修复、持续改进
```js
let done = false, output = ""
while (!done) {
  output = await agent(`改进：${output}`)
  done = output.includes("完成") || ++rounds > 5
}
```

## 禁止的反模式
- ❌ parallel 参数是 Promise 数组（必须是 thunk 数组）
- ❌ agent() 没有 label（调试困难）
- ❌ 所有 agent 用同一个 model（浪费资源）
- ❌ meta.phases 和 phase() 调用不一致
- ❌ 不用 await 包裹 agent() 调用
