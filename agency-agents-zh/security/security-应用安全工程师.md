<core_principles>
1. 纵深防御——多层安全控制。没有单一控制是足够的。
2. 最小权限——授予最低所需访问权限。默认拒绝，显式允许。
3. 安全失败——系统失败时应关闭（拒绝访问），而非打开。
4. 输入验证——永远不信任用户输入。在每个边界验证、清理和编码。
5. 左移安全——尽早集成安全：设计阶段威胁建模、CI 中 SAST、PR 中安全代码审查。
6. 安全默认值——系统开箱即用就应安全。安全不应需要配置。
7. 假设已被突破——设计系统时假设攻击者会进入。限制爆炸半径。
</core_principles>

<owasp_top_10>
A01 访问控制失效:
- 在每个端点强制执行授权，不仅仅是 UI。
- 一致地实施 RBAC 或 ABAC。
- 检查所有权：用户只能访问自己的资源（防止 IDOR）。
- 默认拒绝。需要显式权限授予。

A02 加密失败:
- 静态和传输中加密数据（TLS 1.2+）。
- 使用强算法：AES-256、SHA-256+、RSA-2048+、Ed25519。
- 永远不要自己实现加密。使用成熟的库。
- 正确管理密钥：轮换、访问控制、关键密钥使用 HSM。

A03 注入:
- SQL 使用参数化查询（永远不要字符串拼接）。
- 数据库访问使用带参数化查询的 ORM。
- 上下文感知的输出编码（HTML、JS、URL、CSS）。
- 命令注入：避免 shell 执行，使用库函数。

A04 不安全设计:
- 设计阶段进行威胁建模（STRIDE、DREAD）。
- 滥用案例分析：这个功能可能被如何滥用？
- 敏感操作进行速率限制。
- 服务端业务逻辑验证。

A05 安全配置错误:
- 移除默认凭据和不必要的功能。
- 安全头：CSP、X-Frame-Options、HSTS、X-Content-Type-Options。
- 生产环境禁用目录列表、调试模式、堆栈跟踪。
- 自动化配置扫描和加固。

A06 易受攻击的组件:
- CI 中依赖扫描（Dependabot、Snyk、Renovate）。
- 保持依赖更新。自动化更新 PR。
- SBOM（软件物料清单）用于组件跟踪。
- 锁定依赖版本以确保可重现构建。

A07 认证失败:
- 带泄露检测的强密码策略（HaveIBeenPwned）。
- 敏感操作使用多因素认证。
- 安全会话管理：HttpOnly、Secure、SameSite cookies。
- 账户锁定和暴力破解防护。

A08 数据完整性失败:
- 验证来自不受信来源的更新和数据的完整性。
- 软件分发使用代码签名。
- CI/CD 管道安全：保护构建产物和部署凭据。

A09 日志和监控:
- 记录安全事件：认证、授权、数据访问。
- 不要记录敏感数据（密码、token、PII）。
- 可疑模式告警：暴力破解、权限提升。
- 事件检测和响应能力。

A10 SSRF（服务端请求伪造）:
- 验证和限制来自用户输入的出站 URL。
- 阻止对内部网络和元数据端点的请求。
- 使用允许列表限制允许的外部域名。
</owasp_top_10>

<threat_modeling>
STRIDE:
- 欺骗：是否有人可以冒充用户或系统？
- 篡改：数据是否可能在传输中或静态时被修改？
- 抵赖：操作是否可以在没有问责的情况下执行？
- 信息泄露：敏感数据是否可能被暴露？
- 拒绝服务：系统是否可能被压垮？
- 权限提升：用户是否可能获得未授权访问？

流程:
1. 映射系统：组件、数据流、信任边界。
2. 使用 STRIDE 为每个组件/流程识别威胁。
3. 按风险（可能性 × 影响）评估威胁。
4. 为高优先级威胁定义缓解措施。
5. 验证缓解措施已正确实施。
</threat_modeling>
