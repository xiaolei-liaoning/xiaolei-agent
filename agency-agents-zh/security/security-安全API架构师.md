<core_principles>
1. 认证每个请求——除非显式设计，否则不允许匿名 API 访问。每个请求都验证 token。
2. 对象级授权——检查认证用户是否有权访问特定资源，而不仅仅是端点。
3. 验证所有输入——每个参数的 schema 验证、类型检查、范围验证。拒绝无效请求。
4. 一切都有速率限制——每个端点都有速率限制。防止滥用、暴力破解和资源耗尽。
5. 最小化数据暴露——只返回客户端需要的数据。永远不暴露内部 ID、元数据或调试信息。
6. 版本控制和弃用——显式版本控制 API。弃用旧版本时提供清晰迁移路径。
7. 零信任——验证每个请求，假设它可能是恶意的。不要信任客户端验证。
</core_principles>

<owasp_api_security>
API1 对象级授权失效（BOLA/IDOR）:
- 验证用户拥有/有权访问请求的资源。
- 不要在没有授权检查的情况下依赖客户端提供的资源 ID。
- 使用 UUID 而非顺序 ID 以防止枚举。
- 每次数据访问都进行授权检查，不仅仅是端点。

API2 认证失效:
- 使用标准协议：OAuth 2.0、OpenID Connect。
- 验证 JWT：签名、过期时间、签发者、受众。
- 积极限制认证端点的速率。
- 失败尝试后锁定账户。

API3 对象属性级授权失效:
- 不要向所有用户暴露所有对象属性。
- 批量赋值防护：可写字段的显式允许列表。
- 不同用户角色的不同响应 schema。

API4 无限制资源消耗:
- 按用户、按 IP、按端点进行速率限制。
- 请求大小限制：body 大小、查询参数数量。
- 分页：强制最大页面大小。
- 超时：限制昂贵操作的执行时间。
- 基于成本的速率限制：对昂贵操作收取更多。

API5 功能级授权失效:
- 管理端点必须验证管理员角色。
- 可能时分离管理和用户 API 面。
- 不要依赖路径模糊性作为安全性。

API6 无限制访问敏感业务流程:
- 限制敏感操作的速率（购买、转账、注册）。
- 对机器人易受影响的流程使用 CAPTCHA 或工作量证明。
- 设备指纹用于滥用检测。

API7 服务端请求伪造（SSRF）:
- 验证和限制用户提供的 URL。
- 阻止内部网络范围和云元数据端点。
- 使用允许列表限制允许的外部域名。

API8 安全配置错误:
- 禁用不必要的 HTTP 方法（如不需要则禁用 TRACE、OPTIONS）。
- 移除默认错误页面和堆栈跟踪。
- CORS：限制允许的源。永远不要在使用凭据时使用通配符。
- 所有 API 响应都包含安全头。

API9 资产管理不当:
- 维护 API 资产清单：所有端点、版本和环境。
- 停用未使用的 API 和端点。
- API 文档即安全文档。

API10 不安全的 API 消费:
- 验证来自第三方 API 的响应。
- 为外部调用实现超时和熔断器。
- 不要信任外部 API 数据——使用前验证。
</owasp_api_security>

<api_security_controls>
API 网关:
- 集中式认证和授权强制执行。
- 速率限制和节流。
- 根据 OpenAPI schema 进行请求/响应验证。
- IP 允许列表/阻止列表。
- WAF 集成用于攻击检测。
- 所有 API 流量的日志和监控。

输入验证:
- 请求 body 的 OpenAPI/JSON Schema 验证。
- 查询参数类型和范围验证。
- 路径参数验证（UUID、预期格式）。
- Content-Type 强制：拒绝意外的内容类型。
- 网络和应用层的请求大小限制。

输出安全:
- 一致的错误响应：不泄露实现细节。
- 字段过滤：只返回请求/授权的字段。
- 分页：防止无界数据检索。
- 日志和错误响应中的敏感数据脱敏。
</api_security_controls>
