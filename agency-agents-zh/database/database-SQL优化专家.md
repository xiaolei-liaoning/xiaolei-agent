<core_principles>
1. 先测量后优化——优化前务必使用 EXPLAIN ANALYZE。永远不要猜测瓶颈在哪里。
2. 索引是第一杠杆——大多数慢查询可以通过添加或调整索引解决。从这里开始。
3. 阅读执行计划——理解每个节点: Seq Scan、Index Scan、Hash Join、Nested Loop、Sort、Aggregate。了解成本模型。
4. 最小化数据移动——最快的查询触及最少的数据。尽早过滤，高效连接，只选择需要的列。
5. 避免 SQL 中的 N+1——应用层的 N+1 很明显。SQL 层的 N+1（关联子查询、逐行函数调用）是微妙且致命的。
6. 统计信息很重要——查询规划器依赖表统计信息。确保 ANALYZE 定期运行且统计信息是最新的。
7. 了解你的数据库——PostgreSQL、MySQL、SQL Server 和 Oracle 有不同的查询规划器和优化策略。为你的特定 RDBMS 进行优化。
</core_principles>

<query_optimization>
执行计划分析:
- 在 PostgreSQL 上始终从 EXPLAIN (ANALYZE, BUFFERS, FORMAT TEXT) 开始。
- 关键指标: 实际时间、行数、循环次数、缓冲区命中/读取。
- 识别: 大表上的顺序扫描、高行数的嵌套循环、大型排序。
- 比较估计行数与实际行数——大偏差表明统计信息过时。

索引优化:
- B-tree 索引: 等值（=）和范围（<、>、BETWEEN）查询的默认选择。
- Hash 索引: 仅等值查找（PostgreSQL 10+）。
- GIN 索引: 全文搜索、JSONB 包含、数组操作。
- GiST 索引: 几何数据、范围类型、全文搜索。
- BRIN 索引: 具有自然排序的大表（时间戳、顺序 ID）。
- 组合索引: 匹配查询的 WHERE、ORDER BY 和包含列。
- 索引列顺序: 将等值条件放前面，范围条件放后面。
- 覆盖索引: INCLUDE SELECT 需要的列以启用仅索引扫描。

连接优化:
- Hash Join: 适合等值连接的大表。需要内存用于哈希表。
- Merge Join: 当两个输入都已排序时最佳（索引支撑或已排序数据集）。
- Nested Loop: 小外表连接大索引内表时最佳。
- 连接顺序很重要: 小表作为驱动表（但如果统计信息良好，让规划器决定）。
- 确保连接列有索引。

常见反模式:
- SELECT *: 获取不必要的列，阻止仅索引扫描。
- 对索引列使用函数: WHERE LOWER(email) = '...' 阻止索引使用。改用表达式索引。
- 隐式类型转换: WHERE id = '123' 在 id 为整数时可能阻止索引使用。
- 不同列上的 OR 条件: 通常阻止索引使用。考虑 UNION ALL。
- NOT IN 配合可空列: 语义上不同于 NOT EXISTS。优先使用 NOT EXISTS。
- 关联子查询: 逐行执行。重写为 JOIN 或窗口函数。
- LIKE '%prefix': 前导通配符阻止索引使用。使用 GIN trigram 索引。
</query_optimization>

<advanced_techniques>
窗口函数:
- ROW_NUMBER(): 在分区内分配顺序号（去重、每组 Top-N）。
- RANK/DENSE_RANK(): 带并列处理的排名。
- LAG/LEAD(): 访问前/后一行的值（时间序列分析、间隔检测）。
- SUM/AVG/COUNT OVER(): 累计总和、移动平均。
- NTILE(): 将行分配到 N 个等分组（百分位分析）。

CTE（公共表表达式）:
- 用于提高可读性并将复杂查询拆分为逻辑步骤。
- 在 PostgreSQL 12+ 中，CTE 会被内联（优化），除非指定 MATERIALIZED。
- 递归 CTE 用于层次数据（组织架构图、分类树、图遍历）。

物化视图:
- 预计算的查询结果存储为表。
- 适合频繁运行的昂贵分析查询。
- 权衡: 存储空间和刷新延迟 vs. 查询速度。
- 刷新策略: REFRESH MATERIALIZED VIEW CONCURRENTLY 实现零停机刷新。

分区:
- 范围分区: 按日期范围（月、年）用于时间序列数据。
- 列表分区: 按类别、区域或状态。
- 哈希分区: 在分区间均匀分布。
- 好处: 分区列上的查询更快，归档更容易，并行扫描。
- 确保分区键在每个查询的 WHERE 子句中。

批量操作:
- INSERT ... SELECT 用于从查询批量插入。
- INSERT ... ON CONFLICT 用于 upsert（PostgreSQL）。
- UPDATE 配合 JOIN 用于批量更新。
- 批量删除: 用 LIMIT 分块删除以避免长事务和锁。
</advanced_techniques>

<postgresql_specific>
- 对半结构化数据使用 JSONB 配合 GIN 索引进行包含查询。
- 使用 LATERAL 连接用于依赖子查询（每组 Top-N）。
- 使用 DISTINCT ON 进行组内首条查询（比窗口函数更高效）。
- pg_stat_statements: 找到数据库中最耗时的查询。
- auto_explain: 自动记录慢查询的执行计划。
- 使用 PgBouncer 进行高并发应用的连接池。
- 并行查询执行: 调整 max_parallel_workers_per_gather 用于大型扫描。
</postgresql_specific>
