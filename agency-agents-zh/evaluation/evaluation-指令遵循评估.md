================================================================================
提示词名称: 指令遵循评估
描述: 框架，用于衡量 AI 在提示词中遵循特定指令、约束和格式要求的程度。
使用场景:
  - 测试提示词的清晰度和有效性
  - 确保输出格式合规
  - 验证约束遵循
  - 衡量提示词控制力
================================================================================

<evaluation_criteria>
格式合规:
- 遵循请求的结构（JSON、markdown 等）
- 包含所有必需部分
- 遵循长度约束
- 使用指定的格式

约束遵循:
- 不超出 token 限制
- 遵循风格指南
- 遵守禁止操作
- 遵循范围限制

完整性:
- 回应了请求的所有部分
- 包含所需元素
- 覆盖了指定主题
- 提供了请求的示例

准确性:
- 正确理解指令
- 遵循多步指示
- 处理条件逻辑
- 遵循优先级
</evaluation_criteria>

<scoring_rubric>
评分（0-10）:
10: 完美的指令遵循
8-9: 遵循所有主要指令，有轻微偏差
6-7: 遵循大多数指令，遗漏了一些
4-5: 部分合规，有显著差距
2-3: 指令遵循差
0-1: 忽略大多数指令

扣分规则:
- 缺少必需部分: -2 分
- 格式错误: -2 分
- 忽略约束: 每违反一次 -1 分
- 回复不完整: -3 分
- 误解指令: -2 分
</scoring_rubric>

<test_scenarios>
格式测试:
```
指令: "以 JSON 格式回复，包含键: name、age、city"
预期: 有效的 JSON，恰好包含这些键
失败: 纯文本、缺少键、多余键

指令: "提供恰好 3 个示例"
预期: 恰好 3 个示例
失败: 2 个示例、4 个示例或模糊的"几个示例"

指令: "回复控制在 100 字以内"
预期: 100 字或更少
失败: 150 字
```

约束测试:
```
指令: "不要使用任何外部库"
预期: 纯原生代码
失败: 导入了外部包

指令: "不使用技术术语进行解释"
预期: 简单、易懂的语言
失败: 大量使用技术术语

指令: "只关注安全方面"
预期: 以安全为中心的回复
失败: 讨论了性能、功能等
```

多步测试:
```
指令: "首先分析代码，然后建议改进，最后提供重构版本"
预期: 按顺序三个独立部分
失败: 直接跳到重构，跳过分析，顺序错误
```
</test_scenarios>
