================================================================================
提示词名称: 幻觉检测框架
描述: 方法论，用于检测 AI 何时生成虚假、编造或不可验证的信息，而非准确的回复。
使用场景:
  - 验证 AI 输出的事实准确性
  - 检测编造的 API 或函数
  - 识别虚假的文档引用
  - 确保生产使用的可靠性
================================================================================

<hallucination_types>
事实幻觉:
- 编造的统计数据或数字
- 虚假的历史事实
- 不正确的技术规格
- 捏造的研究引用

代码幻觉:
- 不存在的 API 或函数
- 不正确的函数签名
- 编造的库方法
- 无效的配置选项

文档幻觉:
- 链接到不存在的页面
- 虚假的功能声称
- 不正确的版本信息
- 捏造的最佳实践

逻辑幻觉:
- 自相矛盾的陈述
- 不可能的场景
- 循环推理
- 不一致的解释
</hallucination_types>

<detection_methods>
自动化检查:
- 在文档中验证 API/函数是否存在
- 检查链接返回 200 状态码
- 验证代码语法和编译
- 与官方文档交叉引用
- 测试代码执行

一致性检查:
- 比较相同提示词的多次生成
- 检查内部矛盾
- 跨不同回复验证事实
- 寻找信心缓和用语（"可能"、"或许"）

验证策略:
- 运行生成的代码看是否能工作
- 检查官方文档
- 搜索提到的功能/API
- 用已知事实验证
- 用真实数据测试

危险信号:
- 没有来源的过于具体的细节
- 对不确定的事情做出自信的陈述
- 编造的版本号或日期
- 引用不存在的资源
- 看起来合理但不能工作的代码
</detection_methods>

<hallucination_scoring>
严重级别:

严重（危险）:
- 虚假信息导致安全漏洞
- 不正确代码导致数据丢失
- 错误配置导致系统故障
- 虚假合规声明导致法律问题

高（误导性）:
- 看起来正确但不能工作的代码
- 虚假的 API 文档
- 不正确的最佳实践
- 编造的框架功能

中（令人困惑）:
- 轻微的事实错误
- 过时信息被呈现为最新
- 模糊的陈述
- 未经验证的声称

低（无害）:
- 不确定的措辞
- 过度泛化
- 轻微的不一致
- 明确标记的推测
</hallucination_scoring>

<prevention_strategies>
提示词工程:
- 要求事实引用
- 要求承认不确定性
- 需要时说"我不知道"
- 要求验证步骤
- 限制推测

系统设计:
- 实施事实检查层
- 使用 RAG 实现基于事实的回复
- 添加验证工具
- 启用网络搜索获取最新信息
- 保持知识截止日期意识

生成后:
- 自动化验证检查
- 关键输出的人工审查
- 测试生成的代码
- 验证链接和引用
- 交叉检查事实
</prevention_strategies>
