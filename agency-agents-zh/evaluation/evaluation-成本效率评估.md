================================================================================
提示词名称: 成本效率评估
描述: 框架，用于评估提示词的成本效益，衡量 token 用量、API 成本和每美元的价值产出。
使用场景:
  - 优化提示词以降低 API 成本
  - 比较成本与质量的权衡
  - 为生产部署做预算
  - 识别昂贵的提示词模式
================================================================================

<cost_metrics>
Token 用量:
- 每次请求的输入 token 数
- 每次请求的输出 token 数
- 每个任务的总 token 数
- Token 效率（每 token 的价值）

API 成本:
- 每次请求的成本
- 每个完成任务的成本
- 每个用户会话的成本
- 大规模时的月度预估成本

效率比率:
- 每个成功输出的成本
- 每美元的质量分数
- 每 $100 完成的任务数
- 投入产出比（交付的价值 vs 成本）
</cost_metrics>

<optimization_strategies>
减少输入 Token:
- 移除不必要的上下文
- 使用更短的系统提示词
- 压缩示例
- 引用外部文档而非内嵌

减少输出 Token:
- 要求简洁的回复
- 使用结构化格式（JSON vs 散文）
- 适当设置 max_tokens
- 在不需要时避免冗长的解释

提高成功率:
- 更好的提示词 = 更少重试
- 清晰的指令 = 首次正确
 = 尽早捕获错误

使用更便宜的模型:
- 测试更小的模型是否能完成任务
- 使用分层方案（先用便宜模型，需要时再用贵的）
- 缓存常见回复
</optimization_strategies>

```
- 每月 1K 次请求: $[金额]

效率指标:
- 每美元的质量分数: [分数/$]
- 每 $100 的任务数: [数量]

- [降低成本的具体建议]

[成本是否合理的分析]
```
</output_format>
