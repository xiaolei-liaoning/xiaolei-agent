================================================================================
提示词名称: 延迟与性能评估
描述: 框架，用于衡量和优化提示词的响应时间、吞吐量和整体系统性能。
使用场景:
  - 优化提示词以满足生产环境的延迟要求
  - 识别性能瓶颈
  - 比较提示词效率
  - 满足 SLA 要求
================================================================================

<performance_metrics>
延迟指标:
- 首 token 时间（TTFT）: 响应开始的速度
- 每输出 token 时间: 生成速度
- 总响应时间: 端到端延迟
- P50、P95、P99 延迟: 分布分析

吞吐量指标:
- 每秒请求数
- 每秒 token 数
- 并发请求能力
- 队列等待时间

效率指标:
- 每美元每秒 token 数
- 每 1K token 的延迟
- 缓存命中率
- 重试率
</performance_metrics>

<optimization_strategies>
减少输入 Token:
- 更短的系统提示词
- 压缩上下文
- 移除冗余信息
- 使用引用而非全文

减少输出 Token:
- 设置适当的 max_tokens
- 要求简洁的回复
- 使用结构化格式
- 流式传输响应以提升感知速度

改善缓存:
- 缓存常见提示词
- 复用系统提示词
- 缓存嵌入
- 使用提示词缓存功能

并行处理:
- 批量处理独立请求
- 使用 async/await
- 实现请求池
- 跨端点负载均衡
</optimization_strategies>

<benchmarking_protocol>
测试设置:
1. 定义测试场景（简单、中等、复杂）
2. 创建有代表性的测试用例（N=50+）
3. 控制变量（模型、温度等）
4. 衡量基线性能
5. 多次运行测试以保证一致性

测量:
- 记录开始和结束时间戳
- 追踪 token 数（输入/输出）
- 监控 API 速率限制
- 记录错误和重试
- 在不同负载下测量

分析:
- 计算均值、中位数、标准差
- 识别异常值
- 发现性能模式
- 与 SLA 目标比较
</benchmarking_protocol>
