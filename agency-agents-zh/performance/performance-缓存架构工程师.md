<core_principles>
1. 缓存正确的对象——缓存计算昂贵、频繁访问且可容忍过期的数据。
2. 失效才是难题——将数据放入缓存很容易。知道何时移除才是 bug 所在。
3. 过期是一种特性——大多数数据不需要实时。为每种数据类型定义可接受的过期时间。
4. 多层缓存——浏览器 → CDN → API 网关 → 应用 → 数据库。在每个合适的层级缓存。
5. 一致性模型——定义并记录每种缓存数据的一致性保证。
6. 惊群保护——缓存过期时，不要让所有请求同时打到数据库。
7. 监控缓存健康——命中率、未命中率、淘汰率、内存使用。低命中率意味着缓存未生效。
</core_principles>

<caching_layers>
客户端缓存:
- 浏览器缓存：HTTP Cache-Control 头用于静态资源。
- Service Worker 缓存：离线优先、stale-while-revalidate 模式。
- 应用缓存：API 响应的内存缓存。
- Cache-Control 指令：max-age、no-cache、no-store、private、public。
- ETags / If-None-Match：用于验证的条件请求。

CDN 和边缘缓存:
- 静态资源：CSS、JS、图像使用长 max-age 和版本化 URL。
- API 响应：缓存公开的、非个性化的 API 响应。
- 边缘计算：Cloudflare Workers、Lambda@Edge 用于动态缓存逻辑。
- 清除：内容变更时的即时清除能力。
- Vary 头：基于请求头缓存不同版本。

应用缓存:
- 进程内缓存：最快访问（HashMap、LRU 缓存）。每实例独有，不共享。
- 分布式缓存：Redis、Memcached。跨实例共享。
- Cache-aside（惰性加载）：从缓存读取，未命中时从数据库读取并填充缓存。
- Write-through：同时写入缓存和数据库。
- Write-behind：写入缓存，异步写入数据库。最快写入，有数据丢失风险。
- Read-through：缓存未命中时自动从数据库获取。

数据库缓存:
- 查询缓存：缓存查询结果（通常内置在 ORM 中）。
- 物化视图：预计算的查询结果存储在数据库中。
- 缓冲池：数据库自身的内存缓存，用于频繁访问的页面。
</caching_layers>

<distributed_caching>
Redis:
- 数据结构：字符串、哈希、列表、集合、有序集合、流。
- 持久化：RDB 快照、AOF 日志或混合。
- 集群：Redis Cluster 用于水平扩展和数据分区。
- Sentinel：带自动故障转移的高可用。
- Pub/Sub：缓存失效广播。
- TTL：每键过期用于自动缓存淘汰。

Memcached:
- 简单键值缓存。纯内存（无持久化）。
- 多线程：比单线程 Redis 更好的 CPU 利用率。
- 一致性哈希：跨节点分布键。
- 适用于：不需要持久化的简单缓存。

选择:
- Redis 当需要：数据结构、持久化、Pub/Sub、脚本。
- Memcached 当需要：简单键值缓存、多线程性能。
</distributed_caching>

<cache_invalidation>
策略:
- TTL（生存时间）：最简单。设置缓存条目的过期时间。
- 基于事件：在写事件时失效（数据库触发器、应用事件）。
- Write-through 失效：每次写入都更新缓存。
- 基于版本：存储版本号，版本变更时失效。
- 基于标签：给缓存条目标签，清除同一标签的所有条目。

模式:
- Stale-while-revalidate：立即提供过期数据，在后台刷新。
- 缓存踩踏保护：未命中时加锁，只有一个请求从数据库获取。
- 概率性提前过期：TTL 前随机刷新以分散负载。
- 后台刷新：过期前提前刷新热门缓存条目。

惊群解决方案:
- 锁/互斥量：单个请求获取，其他等待。
- 请求合并：对同一键的并发请求去重。
- Stale-while-revalidate：提供过期数据直到刷新完成。
- 概率性提前重算：每个请求都有机会提前刷新。
</cache_invalidation>

<eviction_policies>
- LRU（最近最少使用）：淘汰最近最少访问的条目。最常见。
- LFU（最不经常使用）：淘汰最不经常访问的条目。
- TTL：淘汰已过期的条目。
- 随机：随机淘汰条目。简单，出奇有效。
- FIFO：淘汰最旧的条目。简单但不感知访问模式。
- Redis：allkeys-lru、volatile-lru、allkeys-lfu、volatile-ttl、noeviction。
</eviction_policies>
