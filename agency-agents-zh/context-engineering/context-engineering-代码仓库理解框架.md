================================================================================
提示词名称: 代码仓库理解框架
描述: AI 分析和理解整个代码仓库的系统化方法，包括架构、依赖、模式和约定。
使用场景:
  - 帮助 AI 快速熟悉新代码仓库
  - 生成架构文档
  - 理解遗留代码
  - 规划重构或迁移
================================================================================

<understanding_process>
步骤 1: 项目结构分析
- 识别项目类型（Web 应用、库、CLI 工具等）
- 梳理目录结构和组织方式
- 定位配置文件（package.json、requirements.txt 等）
- 识别构建和部署文件
- 查找文档（README、docs 文件夹）

步骤 2: 依赖分析
- 列出所有依赖及其用途
- 识别框架和主要库
- 梳理依赖关系
- 检查过时或有漏洞的依赖
- 理解版本约束

步骤 3: 入口点识别
- 找到主要入口点（main.py、index.js 等）
- 识别 API 路由和端点
- 定位 CLI 命令
- 梳理初始化流程

步骤 4: 代码模式分析
- 识别架构模式（MVC、微服务等）
- 检测使用的设计模式
- 理解命名约定
- 识别代码组织原则
- 找到通用抽象和工具函数

步骤 5: 数据流映射
- 追踪数据从输入到输出的流程
- 识别数据模型和 schema
- 梳理数据库交互
- 理解状态管理
- 追踪 API 请求/响应流程

步骤 6: 测试策略
- 定位测试文件和框架
- 理解测试覆盖率
- 识别测试模式
- 查找 CI/CD 配置

步骤 7: 文档综合
- 总结项目目的和架构
- 记录关键组件及其关系
- 识别文档缺失的领域
- 建立系统的心理模型
</understanding_process>

<analysis_techniques>
静态分析:
- 不执行代码即可读取文件结构
- 解析 import/require 语句
- 分析函数签名和类型
- 识别公开 API 与内部代码

模式识别:
- 检测框架约定（Rails、Django、Express）
- 识别常见模式（Repository、Factory、Observer）
- 识别架构风格
- 发现反模式和代码异味

依赖图:
- 构建模块依赖图
- 识别核心模块与外围模块
- 发现循环依赖
- 检测紧耦合组件

复杂度指标:
- 统计每个模块的代码行数
- 度量圈复杂度
- 识别大型文件/函数
- 发现深层嵌套代码
</analysis_techniques>

<context_optimization>
上下文中应包含的内容:
- 项目 README 和主要文档
- 关键配置文件
- 主要入口点
- 核心业务逻辑文件
- 数据模型和 schema
- API 路由定义

上下文中应排除的内容:
- 生成的代码（构建产物）
- 依赖目录（node_modules、venv）
- 大型数据文件
- 二进制文件
- 冗余的测试固定数据

上下文优先级:
1. 与当前任务直接相关的文件
2. 核心抽象和接口
3. 相关工具函数
4. 相关测试
5. 影响行为的配置
</context_optimization>
