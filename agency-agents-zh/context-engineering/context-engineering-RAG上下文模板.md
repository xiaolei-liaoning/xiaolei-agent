================================================================================
提示词名称: RAG 上下文模板
描述: 用于在 RAG（检索增强生成）系统中构建检索上下文的模板，以最大化相关性并减少噪声。
使用场景:
  - 构建 RAG 应用
  - 将向量搜索与 LLM 集成
  - 基于文档的问答
  - 代码搜索和生成
================================================================================

<rag_architecture>
组件:
1. 检索: 查找相关文档/片段
2. 排序: 按相关性排序
3. 上下文组装: 为 LLM 格式化
4. 生成: LLM 使用上下文生成答案
5. 引用: 将答案链接回来源

检索策略:
- 密集检索（向量相似度）
- 稀疏检索（关键词/BM25）
- 混合检索（结合两者）
- 重排序（改善初始结果）
</rag_architecture>

<context_template>
基本 RAG 提示结构:
```
<retrieved_context>
[来源 1 - 相关度: 0.95]
标题: [文档标题]
内容: [相关片段]
元数据: [日期、作者等]

[来源 2 - 相关度: 0.87]
标题: [文档标题]
内容: [相关片段]
元数据: [日期、作者等]

[来源 3 - 相关度: 0.82]
标题: [文档标题]
内容: [相关片段]
元数据: [日期、作者等]
</retrieved_context>

<instructions>
请仅使用上方检索上下文中提供的信息回答以下问题。如果上下文不包含足够的信息来完整回答，请说明。按编号 [1]、[2]、[3] 引用来源。
</instructions>

<question>
[用户的问题]
</question>

<answer>
[LLM 在此生成带引用的答案]
</answer>
```
</context_template>

<chunking_strategies>
固定大小片段:
- 将文档拆分为 N 个 token/字符
- 简单但可能破坏语义单元
- 典型大小: 500-1000 tokens，重叠 100-200 tokens

语义片段:
- 按段落、章节或句子拆分
- 保留含义但大小不一
- 更适合连贯检索

滑动窗口:
- 重叠片段以保留上下文
- 确保边界处不丢失信息
- 增加存储但提高召回率

层次化片段:
- 父片段（完整章节）
- 子片段（段落）
- 检索子片段，提供父片段作为上下文
</chunking_strategies>

<metadata_enrichment>
每个片段应包含的元数据:
- 来源文档标题/URL
- 章节标题
- 作者和日期
- 文档类型（代码、文档、博客）
- 相关度分数
- 片段在文档中的位置

好处:
- LLM 可以评估来源可信度
- 用户可以验证信息
- 支持按元数据过滤
- 提高引用质量
</metadata_enrichment>

<advanced_rag_patterns>
多查询 RAG:
- 从用户问题生成多个搜索查询
- 为每个查询检索
- 合并并去重结果

迭代式 RAG:
- 检索初始上下文
- 生成部分答案
- 识别信息缺口
- 检索额外上下文
- 优化答案

假设文档嵌入（HyDE）:
- 生成假设性答案
- 嵌入假设性答案
- 搜索相似的真实文档
- 使用真实文档生成实际答案

自检索 RAG:
- 检索上下文
- 生成答案
- 自我评估答案质量
- 需要时检索更多
- 优化答案
</advanced_rag_patterns>

<quality_optimization>
改善检索:
- 更好的嵌入模型（微调后的模型）
- 混合搜索（向量 + 关键词）
- 查询扩展
- 使用交叉编码器重排序

改善上下文:
- 移除冗余片段
- 按相关性排序（最相关在前）
- 限制为前 K 个片段（通常 3-5）
- 包含元数据以提高可信度

改善生成:
- 明确指示仅使用提供的上下文
- 要求引用
- 要求承认不确定性
- 惩罚幻觉
</quality_optimization>

<evaluation_metrics>
检索质量:
- Recall@K: 前 K 个结果中相关文档的百分比
- Precision@K: 前 K 个结果中相关结果的百分比
- MRR（平均倒数排名）: 第一个相关文档的位置

生成质量:
- 答案准确性
- 引用准确性
- 幻觉率
- 答案完整性
- 延迟（检索 + 生成时间）
</evaluation_metrics>
