================================================================================
提示词名称: 记忆提示框架
描述: 为 AI 系统提供跨对话持久记忆的技术，包括上下文管理、摘要和检索。
使用场景:
  - 构建有状态的 AI 助手
  - 在长对话中维持上下文
  - 基于历史记录个性化 AI 响应
  - 管理上下文窗口限制
================================================================================

<memory_types>
短期记忆（对话缓冲区）:
- 对话中最近的消息
- 当前任务上下文
- 即时工作记忆
- 通常保留最近 5-10 轮对话

长期记忆（持久存储）:
- 用户偏好和设置
- 过去对话摘要
- 关于用户/项目的学习事实
- 历史决策和结果

语义记忆（向量存储）:
- 相关的过往对话
- 之前解决过的类似问题
- 相关文档
- 通过相似性搜索检索

情景记忆（事件日志）:
- 特定的过往事件
- 任务完成历史
- 错误模式
- 带时间戳的交互记录
</memory_types>

<context_management>
上下文窗口策略:

1. 滑动窗口:
   - 保留最近 N 条消息
   - 达到限制时丢弃最早的
   - 简单但会丢失长期上下文

2. 摘要:
   - 定期对旧消息进行摘要
   - 用摘要替代详细历史
   - 保留关键信息，减少 token 消耗

3. 分层记忆:
   - 详细的近期记忆
   - 摘要化的中期记忆
   - 长期记忆中的关键事实

4. 选择性保留:
   - 保留重要消息（决策、错误）
   - 丢弃常规交流
   - 按与当前任务的相关性排序
</context_management>

<memory_prompting_patterns>
模式 1: 显式记忆注入
```
<conversation_history>
先前相关上下文:
- 用户偏好 Python 而非 JavaScript
- 项目使用 PostgreSQL 数据库
- 上次任务: 构建了认证系统
</conversation_history>

当前请求: [用户的新请求]
```

模式 2: 摘要化上下文
```
<session_summary>
会话开始: [timestamp]
已完成任务: [list]
关键决策: [list]
当前状态: [description]
</session_summary>

新任务: [用户请求]
```

模式 3: 检索的记忆
```
<relevant_past_interactions>
来自 [date] 的类似任务:
- 问题: [description]
- 解决方案: [approach]
- 结果: [result]
</relevant_past_interactions>

当前任务: [用户请求]
```

模式 4: 渐进式摘要
```
<context_layers>
近期（最近 5 条消息）: [详细]
中期（最近一小时）: [摘要]
长期（本项目）: [仅关键事实]
</context_layers>
```
</memory_prompting_patterns>

<implementation_strategies>
记忆存储:
- JSON 文件用于简单场景
- SQLite 用于结构化查询
- 向量数据库（Pinecone、Weaviate）用于语义搜索
- Redis 用于快速访问近期上下文

记忆检索:
- 时效性: 最近的交互
- 相关性: 与当前任务的语义相似度
- 重要性: 用户标记或高影响力的项目
- 频率: 经常被引用的信息

记忆更新:
- 每次交互后更新
- 用户纠正 AI 时更新
- 用户声明偏好时更新
- 任务完成时更新

记忆修剪:
- 移除过时信息
- 合并冗余记忆
- 归档旧对话
- 尊重隐私（按请求删除）
</implementation_strategies>

<best_practices>
1. 始终包含最近的上下文（最近 2-3 轮对话）
2. 积极进行摘要以节省 token
3. 只检索相关记忆，而非全部
4. 重要交互后更新记忆
5. 允许用户纠正或删除记忆
6. 为所有记忆添加时间戳以便追溯
7. 区分事实与观点/偏好
8. 定期测试记忆检索的准确性
</best_practices>
