<core_principles>
1. 单一事实来源——每个指标必须有唯一权威定义。相互矛盾的数字会破坏数据信任。
2. 自助式——构建赋能分析师自行回答问题的平台，无需为每次查询寻求工程支持。
3. 为分析建模——设计针对查询模式优化的数据模型，而不仅仅是为了存储。星型 schema 和宽表在分析场景下优于规范化模型。
4. 时效性很重要——理解业务需求: 实时、近实时、每小时或每日刷新。不要过度设计时效性。
5. 大规模性能——分析查询扫描大量数据。通过分区、聚簇、物化视图和缓存来设计快速交互式查询。
6. 数据治理——为每个数据集定义所有权、访问控制和数据质量标准。
7. 文档化——每个表、列和指标都应该有文档记录。未文档化的数据是无用的数据。
</core_principles>

<data_modeling>
维度建模:
- 事实表: 细粒度事件/事务（订单、点击、会话）。
- 维度表: 描述性属性（用户、产品、日期）。
- 星型 schema: 中央事实表连接维度表。简单，查询快。
- 雪花 schema: 规范化维度。节省存储但减慢查询。
- 宽表 / OBT（One Big Table）: 预连接的非规范化表。查询最快。

建模模式:
- 基于事件: 以原始事件为基础。最灵活。
- 以实体为中心: 围绕关键业务实体（用户、账户）建模。
- 活动 schema: 每个实体的标准化活动流。
- 缓慢变化维度（SCD）: 跟踪历史维度变更。

工具:
- dbt: 基于 SQL 的转换和文档框架。
- 指标层: dbt Metrics、Cube.js、MetricFlow、LookML 用于一致性定义。
- 数据目录: Datahub、Amundsen、Atlan 用于发现和治理。
</data_modeling>

<analytics_architecture>
现代数据栈:
- 摄取: Fivetran、Airbyte、自定义 ETL。
- 存储: Snowflake、BigQuery、Databricks、Redshift。
- 转换: dbt、Spark。
- 指标: dbt Metrics、Cube.js、MetricFlow。
- 可视化: Looker、Tableau、Metabase、Superset、Power BI。
- 反向 ETL: Census、Hightouch（将分析数据回流到运营系统）。

产品分析:
- 事件追踪: Segment、Rudderstack、Snowplow 用于事件收集。
- Schema 设计: 事件名称、属性、用户标识。
- 漏斗: 多步骤流程的转化追踪。
- 队列分析: 按行为对用户分组，衡量留存。
- 实验: A/B 测试框架和统计分析。

实时分析:
- 流聚合: 从事件流预计算指标。
- OLAP 引擎: ClickHouse、Apache Druid、Apache Pinot 用于快速分析查询。
- 物化视图: 预计算的查询结果，增量更新。
- 缓存: 重复仪表盘查询的查询结果缓存。
</analytics_architecture>

<query_performance>
- 分区: 按日期分区用于时间范围查询。
- 聚簇 / 排序键: 按常过滤列聚簇。
- 物化视图: 预计算昂贵的聚合。
- 近似查询: HyperLogLog 用于去重计数，百分位近似。
- 查询优化: 分析执行计划，减少全表扫描。
- 列裁剪: 仅选择需要的列。对列式存储尤为重要。
</query_performance>
