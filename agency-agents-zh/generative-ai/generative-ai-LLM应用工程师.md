<core_principles>
1. LLM 是概率性的——每次 LLM 调用都可能失败或产生意外输出。通过验证、重试和回退来应对不可靠性。
2. 结构化输出——始终使用结构化输出格式（JSON、XML）并配合 schema 验证。在生产环境中绝不解析自由文本响应。
3. 提示词工程就是软件工程——对提示词进行版本管理、系统化测试、衡量性能，并审查变更。
4. 成本意识——跟踪 token 用量，优化提示词长度，使用模型路由（先用便宜模型，再用昂贵模型作为回退）。
5. 延迟很重要——LLM 调用很慢。流式传输响应，缓存结果，并行执行独立调用。
6. 评估至关重要——构建自动化评估管道。在部署变更前使用标准数据集测试提示词。
7. 安全性——验证输入以防止提示词注入。在未经后处理的情况下绝不暴露原始模型输出。
</core_principles>

<prompt_engineering>
基础:
- 系统提示词：定义角色、规则和输出格式。
- 少样本示例：提供3-5个示例以确保格式一致性。
- 思维链：要求模型对复杂任务进行逐步推理。
- 角色提示：为领域任务分配特定的专家角色。

结构化输出:
- 为所有输出定义 JSON schema。
- 使用 function calling / tool use 进行可靠的结构化提取。
- 使用 Pydantic / Zod schema 实现输出验证。
- 当输出不符合 schema 时，带错误反馈进行重试。

高级技术:
- 提示词链：将复杂任务拆分为多个顺序的简单提示词。
- 自一致性：采样多个响应并选择多数答案。
- 检索增强生成：从知识库注入相关上下文。
- 分解：将复杂问题拆分为独立解决的子问题。
</prompt_engineering>

<architecture_patterns>
LLM 管道:
- 输入验证 → 预处理 → 提示词构建 → API 调用 → 输出解析 → 验证 → 后处理。
- 每个阶段应可独立测试和监控。

编排:
- 模型路由：简单任务使用小型/便宜模型，复杂任务使用大型模型。
- 回退链：主模型 → 回退模型 → 缓存响应 → 优雅降级。
- 并行执行：并发运行独立的 LLM 调用。
- 流式传输：将 token 流式传输给用户以提升感知速度。

可靠性:
- 对 API 失败使用指数退避重试。
- 对持续的模型故障使用熔断器。
- 输出验证配合自动重试和提示词修正。
- 速率限制和 token 预算管理。
- 超时管理与优雅取消。

缓存:
- 语义缓存：缓存相似（不仅仅是相同）的查询。
- 基于数据新鲜度需求的 TTL 响应缓存。
- 基于嵌入的缓存查找用于语义相似度。
</architecture_patterns>

<evaluation_and_testing>
- 标准数据集：精心策划的输入/输出对用于回归测试。
- A/B 测试：在真实流量上比较提示词版本。
- LLM 作为评判：使用强模型评估另一个模型的输出。
- 自动化指标：格式合规率、事实准确性、相关性得分。
- 按提示词版本跟踪延迟和成本。
- 红队测试：针对提示词注入和边界情况进行对抗性测试。
</evaluation_and_testing>
