<core_principles>
1. 清晰优于巧妙——最好的提示词是不含糊的。如果一个人类觉得这个指令令人困惑，模型也会。
2. 具体制胜——模糊的提示词得到模糊的结果。明确指定格式、长度、风格、约束和边界情况处理。
3. 展示而非仅告知——少样本示例比单纯的指令更可靠。向模型展示你想要什么。
4. 结构化输出——为任何需要传递给下游代码的提示词定义输出 schema（JSON、XML）。自由文本输出会破坏生产管道。
5. 衡量一切——使用标准数据集进行 A/B 测试。"感觉更好"不是一个指标。
6. 模型感知——不同模型对同一提示词的响应不同。针对你的目标模型进行优化。
7. 成本意识——更短的提示词成本更低。优化为达到质量目标的最短提示词。
</core_principles>

<prompting_techniques>
基础:
- 零样本：不带示例的直接指令。适用于简单、定义明确的任务。
- 少样本：提供3-5个输入/输出示例。对格式和边界情况至关重要。
- 系统提示词：定义角色、规则、约束和输出格式。
- 角色提示："你是一个[特定专家]..."用于领域特定任务。

推理:
- 思维链（CoT）："逐步思考"或提供推理示例。
- 零样本 CoT：在提示词后附加"让我们逐步思考"。
- 自一致性：采样多个 CoT 响应，取多数答案。
- 思维树：探索多条推理分支。

可靠性:
- 输出格式化：定义 JSON schema，使用分隔符，提供格式示例。
- 约束执行：明确说明不要做什么。
- 边界情况处理：描述如何处理模糊或缺失的输入。
- 置信度信号：要求模型标示不确定性。

高级:
- 提示词链：将复杂任务拆分为顺序提示词。
- 元提示：使用 LLM 生成和优化提示词。
- Constitutional AI：添加批评和修订步骤。
- 检索增强：在任务指令前注入相关上下文。
- 分解：将复杂任务拆分为更简单的子任务。
</prompting_techniques>

<prompt_structure>
最佳结构:
1. 角色/身份——模型应该成为谁。
2. 上下文——背景信息和约束。
3. 任务——清晰、具体的执行指令。
4. 格式——带 schema 定义的精确输出格式。
5. 示例——3-5个覆盖正常和边界情况的多样化示例。
6. 约束——需要避免的内容、长度限制、风格要求。
7. 回退——当任务无法完成时的处理方式。

格式化最佳实践:
- 使用 XML 标签或 markdown 标题分隔各部分。
- 使用编号列表表示顺序指令。
- 使用项目符号列表表示并列约束。
- 使用明确标记（三引号、XML 标签）分隔用户输入。
- 将最重要的指令放在最后（近因偏差）。
</prompt_structure>

<evaluation>
构建评估数据集:
- 50-200个测试用例，覆盖正常、边界和对抗性输入。
- 包含预期输出用于自动化比较。
- 按难度级别和输入类型分层。
- 包含反面示例（模型应该拒绝或说"我不知道"的输入）。

指标:
- 格式合规：输出是否符合预期 schema？
- 准确性：输出是否包含正确信息？
- 忠实度：输出是否基于提供的上下文？
- 相关性：输出是否解决了用户的问题？
- 一致性：相同输入在多次运行中是否产生一致的输出？
- 成本：每次请求的平均 token 数。

评估方法:
- 精确匹配：用于具有确定性答案的结构化输出。
- LLM 作为评判：使用强模型评估输出质量。
- 人工评估：用于主观质量、流畅性、实用性。
- 评分标准：按多个维度和定义的标准打分。

优化循环:
1. 在当前提示词版本上运行评估。
2. 分析失败案例——找出错误中的模式。
3. 修改提示词以解决失败模式。
4. 重新运行评估以衡量改进。
5. 重复直到达到质量目标。
</evaluation>

<cross_model_adaptation>
- GPT-4 / GPT-4o：出色的指令遵循能力，支持系统提示词。
- Claude：长上下文，擅长 XML 结构化提示词，具有 Constitutional 特性。
- Gemini：多模态，擅长结构化输出。
- LLaMA / Mistral：可能需要更明确的格式化，指令遵循能力较弱。
- 在每个目标模型上测试提示词——不要假设可移植性。
- 为关键应用维护特定于模型的提示词变体。
</cross_model_adaptation>
